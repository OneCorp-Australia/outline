OneCorp Outline AI Authoring and Import Guide

Give this file to any AI that is preparing an SOP, training article, sales script, or instructional document for OneCorp’s Outline knowledge base. The AI must follow the output contract below.

Quick decision: use Markdown for an ordinary article. Use standalone HTML whenever different highlight colours carry meaning. Markdown can represent a generic highlight, but it cannot retain the highlight colour.

1. Output contract for the AI

  1. Return one complete, import-ready file. Do not wrap the file in a code fence and do not add an explanation before or after it.
  2. Use a descriptive kebab-case filename, such as handling-price-objections.html or new-starter-onboarding.md.
  3. Save text as UTF-8. Use Australian English unless instructed otherwise.
  4. Preserve the supplied facts and meaning. Do not invent company policies, steps, links, owners, timings, compliance claims, or customer promises.
  5. Start a file being uploaded to Outline with exactly one H1 containing the article title. Use H2, H3, and H4 for the body hierarchy; do not skip heading levels.
  6. When creating or updating a document directly through the OneCorp Outline MCP or API, put the title in the separate title field. The document body must not begin with an H1; start with introductory text or an H2.
  7. Keep formatting semantic and purposeful. Never use colour as the only way to communicate meaning.

2. Choose the output format

Requirement Use Reason
Normal SOP, policy, guide, checklist, or training article Markdown (.md) Portable, readable, and well supported by Outline.
One generic highlight colour only Markdown (.md) Outline supports ==highlighted text==.
Several highlight colours with different meanings HTML (.html) HTML can carry Outline’s colour attribute on each highlight.
Direct AI creation through Outline MCP or API Markdown body The title is passed separately; colour-specific marks are unavailable.
Moving content between Outline workspaces without losing rich state Outline JSON export Markdown export does not preserve highlight colours.

Markdown limitation: raw HTML is disabled when Outline parses a Markdown file. Do not place <mark>, styled <span>, or other HTML inside a .md file to try to retain colours. Every Markdown highlight is the same generic ==highlight== mark.

4. HTML profile for colour-critical documents

Use a standalone .html file when a sales script, training guide, or other article relies on several highlight colours. Use only the supported semantic elements shown here. Outline removes page-level styling and imports the content into its own editor design.

Colour-specific highlight syntax

<mark data-color="#FA551E"><strong>OBJECTION:</strong> “It costs too much.”</mark>

<mark data-color="#B4DC19"><strong>RESPONSE:</strong> Acknowledge the concern, then clarify the value.</mark>

<mark data-color="#3CBEFC"><strong>COACH NOTE:</strong> Pause and let the customer answer.</mark>

The data-color value is the part Outline uses. It must be a hex colour. Use the approved palette below for consistency and reliable editing in Outline.

Outline colour Hex Default OneCorp meaning
Sunset #FA551E OBJECTION / RISK
Smoothie #B4DC19 RESPONSE / ACTION
Neon #3CBEFC COACH NOTE / CONTEXT
Apricot #FED46A CAUTION / VERIFY
Bubblegum #C8AFF0 ESCALATE / SPECIALIST
Coral #FDEA9B CUSTOMER WORDS / EXAMPLE

A legend supplied for a particular document overrides this default mapping. State the legend near the beginning of every colour-coded article. Include a visible label such as OBJECTION: or RESPONSE: inside each highlighted passage so the article is still understandable to people who cannot distinguish the colours.

Reliable HTML patterns

<!doctype html>
<html lang="en-AU">
  <head>
    <meta charset="utf-8" />
    <title>Article title</title>
  </head>
  <body>
    <h1>Article title</h1>
    <p>Introductory paragraph with <strong>bold</strong>,
      <em>italic</em>, <u>underline</u>,
      <del>strikethrough</del>, and <code>inline code</code>.</p>

    <h2>Main section</h2>
    <h3>Subsection</h3>
    <h4>Detail</h4>

    <p><a href="https://example.com">Descriptive link text</a></p>
    <img src="https://example.com/image.png" alt="Useful image description" />

    <ul>
      <li>Bulleted item</li>
    </ul>
    <ol>
      <li>First step</li>
    </ol>

    <ul class="checkbox_list">
      <li data-type="checkbox_item"><p>Incomplete task</p></li>
      <li data-type="checkbox_item" class="checked"><p>Completed task</p></li>
    </ul>

    <blockquote><p>A quotation or important excerpt.</p></blockquote>
    <hr />

    <table>
      <thead>
        <tr><th>Situation</th><th>Response</th></tr>
      </thead>
      <tbody>
        <tr><td>Example</td><td>Action</td></tr>
      </tbody>
    </table>

    <div class="notice-block warning">
      <div class="content">
        <p><strong>Warning:</strong> Complete the compliance check.</p>
      </div>
    </div>

    <div data-type="container_toggle">
      <p><strong>Expandable heading</strong></p>
      <p>Expandable supporting content.</p>
    </div>

    <div class="code-block" data-language="javascript">
      <pre><code>const example = "code";
console.log(example);</code></pre>
    </div>
  </body>
</html>

Notice styles are info, success, tip, and warning. Replace the second class on notice-block to choose the meaning.

Do not generate

  • JavaScript, scripts, forms, iframes, or interactive page behaviour.
  • CSS files, <style> blocks, layout systems, custom fonts, or decorative page design.
  • Foreground text colours. Outline supports background highlights, not a general coloured-font mark.
  • Colour meaning without a written label and a legend in the document.
  • Unsupported custom widgets or copied Word layout such as floating text boxes, columns, page headers, footers, and precise pagination.

5. Working with Microsoft Word documents

A .docx file is acceptable source material and Outline can import it, but Word and Outline use different document models. Treat Word import as a semantic conversion, not a pixel-perfect transfer. Headings, paragraphs, lists, links, tables, images, and common emphasis are the most reliable. Precise colours, layout, fonts, text boxes, and other decorative formatting may be changed or lost.

  1. Give the original Word file to the AI.
  2. Tell it whether the result is a normal article or a colour-critical article and provide the intended colour legend in words.
  3. For a colour-critical article, require standalone HTML using <mark data-color="#HEX">. Do not ask for Markdown or rely on direct Word import to retain the colours.
  4. Compare the generated article with the Word original side by side. Check that no instruction, qualification, objection, response, warning, or compliance wording has moved or changed category.

6. Features to add inside Outline after import

Add these with Outline’s editor after the article has been imported. An external Markdown or HTML file cannot safely recreate their workspace state or permissions:

  • mentions of Outline users, groups, collections, or documents;
  • live Embed blocks and provider-specific media;
  • uploaded file attachments and videos;
  • diagrams and editable Mermaid or diagrams.net content;
  • comments and collaborative suggestions; and
  • template placeholders and workspace template variables.

7. Import into Outline

  1. Open the destination collection or parent document in Outline.
  2. Drag the .md or .html file into the collection, or use the document menu and choose Import document.
  3. Open the imported article and complete the quality checks below before publishing or sharing it.

8. Required quality checks

  • The title is correct and not repeated in the body.

  • Heading levels form a logical outline.

  • Steps and checklist items remain in the correct order.

  • Every link opens the intended destination.

  • Images appear and have useful alternative text.

  • Tables remain readable on a narrow screen.

  • Notices and toggles imported as native Outline blocks.

  • Every colour matches the article’s visible legend.

  • Every coloured passage also has a written category label.

  • Critical wording matches the approved source.

  • Native-only mentions, embeds, attachments, or diagrams have been added.

Final rule: if the article’s meaning depends on several colours, the deliverable is HTML. If it does not, prefer Markdown.
